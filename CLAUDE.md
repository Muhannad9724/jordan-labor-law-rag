## Project 
RAG Project for Jordan work law and Social Security law 

Main Goal: Learning how to build RAG projects and have a project to my resume 

## Deployment goal
This project is meant to be launched publicly with a live URL, not just run locally in a notebook — that's the end target, not a stretch goal. Every architecture/tooling choice from here on (embeddings, vector store, backend, hosting) should be made with "can this actually be deployed and stay up cheaply/reliably" in mind, not just "does this work on my machine." Concretely: favor options with a real free/cheap hosting or managed path (e.g. a vector store that has a hosted tier, an embedding approach that doesn't require a dedicated always-on GPU box) over the locally-fastest option when the two conflict; flag the tradeoff explicitly when they do.

- Search method decided: hybrid via RRF, k=5, w=0.85 (semantic Cohere rank + BM25 keyword rank, BM25 k1=1.5/b=0.75) — tested in `scripts/search_method_evaluation.ipynb` against pure semantic, pure keyword, weighted-sum (beta sweep), 210 RRF (k,w) configs, and a 25-combo BM25 k1/b grid
- Retrieval function built: `src/retrieval.py` (`Retriever` class, importable for the future FastAPI backend), validated in `scripts/retrieval.ipynb` to exactly reproduce the eval numbers (recall@1 0.675, recall@5 0.825, recall@10 0.900, MRR 0.744)
- Generation model decided: `gpt-4o-mini` via OpenRouter (`src/generation.py`'s `get_production_generator()`) — initial Cohere pick was made without comparison, so it got tested head-to-head against Cohere `command-a-03-2025` and Qwen2.5-72B in `scripts/generation_llm_comparison.ipynb`, first on regex citation-matching proxies (GPT-4o-mini: 10/10 correct, 0 fabricated citations, vs 9/10 and 1 each for the others), then on proper LLM-as-judge faithfulness/relevancy scoring (Claude Sonnet 5 via OpenRouter as an independent judge) since citation-matching isn't real faithfulness or relevancy — GPT-4o-mini won there too (faithfulness 5.00 mean/5 min vs 4.82/3 and 4.64/3), and the judge pass caught two real defects the citation check missed: Cohere padding its answer with irrelevant info on an out-of-scope question (relevancy 2/5), and Qwen producing a stray Chinese sentence in one answer. GPT-4o-mini is also ~17x cheaper than Cohere
- Phase 8 done: full 40-question eval run through the production pipeline (`scripts/evaluation_harness.ipynb`) — retrieval exactly matches Phase 6 (recall@1 .675/@5 .825/@10 .900/MRR .744, no regression), generation regex-proxy correct-article rate 33/40 (true rate ~87.5% once 2 regex false-negatives are accounted for — a proxy bug, not a model error), LLM-judge mean faithfulness 4.90/relevancy 4.80 on the full set (vs 5.00/4.91 on the Phase 7 sample). Traced every one of the 7 apparent misses individually: only 1 real generation defect (q07, misattribution) and 1 real retrieval miss (q22, also the only low judge score at faith 3/rel 2) — the rest are the known recall@5-vs-10 cutoff (3 questions) or the regex bug (2 questions). Separately, q09 and q21 each correctly cited the right article from properly-retrieved context but also fabricated one extra ungrounded citation — same failure mode Phase 7 saw from Cohere/Qwen, now reproduced twice by GPT-4o-mini. (Note: an earlier draft of this analysis misread the results table and wrongly claimed q21's correct citation wasn't grounded at all — corrected after re-querying the retriever directly; the lesson being that per-question failure analysis on wrapped pandas output should be re-verified programmatically before writing conclusions.) Three open follow-ups logged for Phase 12 polish, not yet actioned: fix `ARTICLE_NUM_RE` in `src/generation.py` (misses Arabic "للمادة" elided-prefix citations), look at why Article 90 didn't retrieve for q22, and check whether SSL pension articles (62/71/80/85/90) need finer chunking.
- Phase 8b done: tested the two untested generation defaults surfaced by Phase 8 — `top_k` (5 vs 10) × `temperature` (unset/~1.0 vs 0.0), full 40 questions, regex proxy + LLM-judge (`scripts/generation_config_tuning.ipynb`). `temperature=0` didn't help (raised fabrication rate, lowered hit rate at top_k=5) — not adopted. `top_k=10` matched `top_k=5` on hit/fabrication rate but fixed the worst-case judge scores (min faithfulness 2→4, min relevancy 2→3) — traced to q29 (Phase 8's rank-7 retrieval case) going from a real faithfulness failure to no failure once the model actually had the article. **Production default changed: `Retriever.retrieve()` in `src/retrieval.py` now defaults to `top_k=10`** (was 5).
- Phase 8c done, not adopted: tested Cohere `rerank-v3.5` three ways (raw-pool rerank, RRF-then-rerank, vs RRF alone) in `scripts/reranker_evaluation.ipynb`. Reranking fixes the known cross-lingual weakness (recall@10 0.625→0.875) but costs same-language precision (recall@1 0.844→0.719) — RRF wins every same-language metric outright, and same-language is 80% of the eval set. Traced the same-language regression to a concrete cause (q03): several leave provisions share near-identical boilerplate opening phrasing, and the general-purpose reranker pattern-matches on that surface text rather than the specific clause that actually distinguishes the correct article — unlike the embedding model, which was chosen in Phase 4 specifically for accuracy on this corpus. Not adopted; `Retriever` unchanged from Phase 8b (RRF, `top_k=10`).
- Phase 9 done: FastAPI backend (`src/api.py`, `POST /ask` + `GET /health`), `Retriever`/generator built once at startup not per-request, demoed end-to-end (real subprocess + HTTP calls, not just direct Python calls) in `scripts/api_demo.ipynb` for both EN and AR questions. `requirements.txt` added. CORS still wide open, no rate limiting yet — both deferred to Phase 11 deploy.

Per-message RTL detection, collapsible sources panel, pending/error states. Confirmed functionally (static files serve, CORS preflight succeeds from the frontend's origin to the backend) but **not opened in an actual browser** — no browser-automation tool available in this environment, so layout/RTL rendering/real interaction needs a manual check.
